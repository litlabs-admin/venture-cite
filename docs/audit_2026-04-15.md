## P0 — Critical (ship-blockers)

### Security / Authz

**P0-1 — Mass assignment across ~40 write endpoints.** Routes spread `req.body` directly into `storage.create*()` / `storage.update*()`. A caller can set `userId`, `brandId`, `status`, `viewCount`, `citationCount`, `accessTier`, `isAdmin`, and similar fields that the user should never control. Examples: [routes.ts:1356](../server/routes.ts#L1356) (articles create), [routes.ts:1434](../server/routes.ts#L1434) (articles update), plus ~38 others (listicles, BOFU, FAQs, prompts, hallucinations, facts, AI sources, prompt tests, agent tasks, outreach, automation rules, publication targets, emails, posts). **Fix pattern:** every `create*/update*` route must pick an explicit allowlist of fields from `req.body`, then stamp `userId` from `req.user`.

**P0-2 — IDOR on every non-`:brandId` resource route.** The `app.param("brandId", brandIdParamHandler)` fix only covers routes shaped `/:brandId`. Routes shaped `/:id` (where `id` is an article / competitor / citation / faq / prompt / hallucination / agent task / outreach campaign / automation rule) do **not** check ownership. User A can GET/PUT/DELETE any of User B's rows by guessing IDs. Affects ~30 routes. **Fix:** either chain every child entity back to `brand.userId` in storage (e.g. `getArticleByIdForUser`, `getFaqByIdForUser`), or add an `assertOwnership(entity, user)` helper and call it at the top of each handler.

**P0-3 — Global-read endpoints leak cross-tenant data.**
- [routes.ts:343](../server/routes.ts#L343) `/api/dashboard` — returns platform-wide analytics.
- [routes.ts:359](../server/routes.ts#L359) `/api/onboarding-status` — lists all brands/articles/citations.
- [routes.ts:380](../server/routes.ts#L380) `/api/platform-metrics` — aggregates all users.
- [routes.ts:1372](../server/routes.ts#L1372) `/api/articles` (GET) returns every article globally.

All are behind `requireAuthForApi` so they're authenticated, but they don't filter by `req.user.id`. Any logged-in user sees everyone's data.

**P0-4 — `/api/distribute/:articleId` and `/api/geo-rankings/check/:articleId`.** [routes.ts:1610](../server/routes.ts#L1610) and [routes.ts:1750](../server/routes.ts#L1750): each makes up to **15 OpenAI/Perplexity calls per request** in a loop (platforms × prompts), with **no `aiRateLimit`** and no brand-ownership check. Single authenticated user can drain the OpenAI bill.

**P0-5 — SSRF surface on URL-fetch endpoints.** `/api/brands/autofill` [routes.ts:1927](../server/routes.ts#L1927), `/api/brands/create-from-website` [routes.ts:2050](../server/routes.ts#L2050), `/api/ai-crawler-permission-check` [routes.ts:2676](../server/routes.ts#L2676). All fetch a user-supplied URL server-side with no allowlist, no private-IP block, no DNS-rebinding protection. Attacker can hit `http://169.254.169.254/` (cloud metadata), `http://localhost:5432`, internal services, etc.

### Correctness

**P0-6 — Monthly usage reset ignores year.** [databaseStorage.ts:452](../server/databaseStorage.ts#L452): `now.getMonth() !== resetDate.getMonth()`. A Jan-2025 resetDate compared against Jan-2026 = equal months, no reset. Users carry usage across calendar years. **Fix:** compare `year*12 + month`.

**P0-7 — Unvalidated `response.json()` / `response.text()` on upstream fetches.**
- Perplexity call at [routes.ts:1803](../server/routes.ts#L1803) — no `response.ok` check; error bodies parsed as data.
- Website fetches at [routes.ts:1968](../server/routes.ts#L1968) and [routes.ts:2091](../server/routes.ts#L2091) — a 403/500 HTML error page is fed to OpenAI as "brand content" and analyzed straight-faced.

### Frontend

**P0-8 — Raw `fetch()` bypassing Bearer header.**
- [landing.tsx:207](../client/src/pages/landing.tsx#L207) (waitlist — public route, OK, but no `response.ok` check).
- [content.tsx:573](../client/src/pages/content.tsx#L573) (`/api/popular-topics`) — **live route**, will 401 silently.
- [revenue-analytics.tsx:30](../client/src/pages/revenue-analytics.tsx#L30), [ai-traffic.tsx:44](../client/src/pages/ai-traffic.tsx#L44), [community-engagement.tsx:104](../client/src/pages/community-engagement.tsx#L104), [client-reports.tsx:64](../client/src/pages/client-reports.tsx#L64) — all behind `<ComingSoon />` so technically dead code, but the pages are still routable from the router and would crash if the gate is ever lifted.

## P1 — High (fix before launch)

### Backend

**P1-1 — JSON.parse on OpenAI output without try/catch.** [routes.ts:2019](../server/routes.ts#L2019), [routes.ts:2143](../server/routes.ts#L2143), [routes.ts:3106](../server/routes.ts#L3106), [routes.ts:3570](../server/routes.ts#L3570), [routes.ts:3809](../server/routes.ts#L3809). `response_format: json_object` helps but doesn't guarantee well-formed/expected-shape output. Crashes the request on malformed response.

**P1-2 — `humanizeContent` chains 3 OpenAI calls at `max_tokens: 4500` each with no per-user quota** ([routes.ts:530](../server/routes.ts#L530)). Called from `/api/generate-content` and `/api/rewrite-content`. Hostile input ≈ 13.5k tokens per request, behind a 10 req/min IP rate limit.

**P1-3 — Error handler returns `err.message` verbatim in prod.** [index.ts:173](../server/index.ts#L173). Stack-trace-adjacent details leak to clients.

**P1-4 — Migration runner not transactional and not tracked.** [index.ts:145](../server/index.ts#L145): loops `.sql` files and runs each via `pool.query()`. No `schema_migrations` table, no transaction wrapper. A partial failure leaves DB inconsistent and re-runs everything on next boot. Works today only because `0001_auth_sync.sql` is hand-written to be idempotent (`create or replace`, `drop if exists`, `enable row level security`).

**P1-5 — Rate limiter is IP-keyed even though `trust proxy = 1`.** Behind a load balancer, all authenticated users share limits; one noisy IP DoSes everyone else. Key by `req.user?.id ?? req.ip`.

**P1-6 — Stripe webhook has no idempotency guard.** [webhookHandlers.ts:14](../server/webhookHandlers.ts#L14). Stripe retries on 5xx/network errors. Re-processing `customer.subscription.deleted` twice = double-downgrade; re-processing checkout complete = tier granted twice. Track processed `event.id`s in a small table.

**P1-7 — `PERPLEXITY_API_KEY` and `PUBLIC_BASE_URL` read from `process.env` but missing from `server/env.ts` schema.** They fail at first request instead of at boot.

**P1-8 — Unhandled Stripe event types silently dropped** ([webhookHandlers.ts:101](../server/webhookHandlers.ts#L101)) — `default:` is a no-op. Add at least a `console.warn`.

**P1-9 — `/api/beta/validate` double-use.** [routes.ts:275](../server/routes.ts#L275) — `useBetaInviteCode()` is called without verifying the code hasn't already been redeemed by the same user. Needs confirmation on the DB constraint, but worth grepping.

**P1-10 — DeepSeek ranking is faked.** [routes.ts:1831](../server/routes.ts#L1831): `AI_PLATFORMS` lists DeepSeek but the else-branch uses OpenAI to simulate it. Users pay for data they aren't getting.

**P1-11 — `platformUrl` field stores generated content.** [routes.ts:1702](../server/routes.ts#L1702) writes the full formatted post into a column named `platformUrl`. Either the column is misnamed or the write is wrong.

### Database

**P1-12 — Storage methods that read globally.** [databaseStorage.ts](../server/databaseStorage.ts): `getCitations()`, `getBrands()`, `getArticles()`, `getDistributions()`, `getGeoRankings()`, `getGeoRankingsByPlatform()`, `getPublicationMetrics()`, `getPublicationReferences()`, `getCompetitors()`, `getCompetitorLeaderboard()`, `getAllBetaInviteCodes()`, `getAnalytics()` — none take `userId`. These are the engines behind P0-3; even after fixing routes, leaving these available is a footgun for future code.

**P1-13 — Missing `onDelete` on nearly every FK.** `articles.brandId`, `distributions.articleId`, `keywordResearch.brandId`, `geoRankings.articleId`, `brandVisibilitySnapshots.brandId`, `publicationReferences.articleId`, `competitors.brandId`, `listicles.brandId`, `wikipediaMentions.brandId`, `bofuContent.brandId`, `faqItems.brandId`/`articleId`, `brandMentions.brandId`, `promptPortfolio.brandId`, `citationQuality.brandId` — all lack cascade. Deleting a brand leaves orphan rows that still show up in global queries.

**P1-14 — `*.brandId` columns are nullable** on competitors, listicles, wikipediaMentions, bofuContent, faqItems, brandMentions, promptPortfolio, citationQuality. Allows orphan rows at insert-time.

**P1-15 — No `(brandId, slug)` unique constraint on articles.** [schema.ts:115](../shared/schema.ts#L115): `slug` unique globally, so two different brands can't have an article at the same slug.

**P1-16 — N+1 in `getCompetitorLeaderboard`** ([databaseStorage.ts:599](../server/databaseStorage.ts#L599)) and `discoverPublications` ([databaseStorage.ts:1467](../server/databaseStorage.ts#L1467)).

**P1-17 — `sendOutreachEmail` is a `Math.random() > 0.15` mock** ([databaseStorage.ts:1564](../server/databaseStorage.ts#L1564)). Real feature or scheduled to be wired? Either way, surfacing it.

### Frontend

**P1-18 — `response.json()` without `response.ok` in auth forms.** [login.tsx:29](../client/src/pages/login.tsx#L29), [register.tsx:41](../client/src/pages/register.tsx#L41), [forgot-password.tsx:26](../client/src/pages/forgot-password.tsx#L26). Error branch is `try{}catch{}` which swallows the parse error, and the user sees "undefined".

**P1-19 — `staleTime: Infinity` + shared-browser risk.** [queryClient.ts:52](../client/src/lib/queryClient.ts#L52). Combined with `queryClient.clear()` on logout this is mostly OK, but any mutation that forgets to invalidate leaves permanently-stale data. Worth a pass over every `useMutation` call.

**P1-20 — Query error states missing on dashboards.** [home.tsx:231](../client/src/pages/home.tsx#L231), [dashboard.tsx:27](../client/src/pages/dashboard.tsx#L27), [citations.tsx:69](../client/src/pages/citations.tsx#L69). Loading handled, error not — failed requests render undefined data and crash children.

**P1-21 — 10-second `refetchInterval` hammers the server** ([dashboard.tsx:29](../client/src/pages/dashboard.tsx#L29)), no backoff on 401 or tab-hidden.

**P1-22 — `reset-password.tsx` useEffect has no try/catch around `supabase.auth.getSession()`** and doesn't clean up its `onAuthStateChange` subscription if unmounted mid-promise.

## P2 — Medium

- **P2-1** — `tsconfig.json` has `skipLibCheck: true`. Hides real type errors in deps.
- **P2-2** — `ws` package in [package.json](../package.json) has no importers. Dead dep.
- **P2-3** — `RESEND_API_KEY` in env.example is never read. Dead config.
- **P2-4** — Response body logged in full by the request logger ([index.ts:109](../server/index.ts#L109)) — can log tokens/PII if any handler ever echoes them.
- **P2-5** — Health check only runs `SELECT 1`. Doesn't verify write path or migration state.
- **P2-6** — Graceful shutdown: `server.close()` doesn't await `pool.end()`, they race.
- **P2-7** — CORS allowlist duplicates `http://localhost:5000` with `APP_URL`. Trivial.
- **P2-8** — OpenAI SDK has no `timeout` configured. Hanging upstream blocks a worker.
- **P2-9** — `landing.tsx` waitlist + several forms lack Zod validation; rely on `required` attr only.
- **P2-10** — `ai-visibility.tsx` stores progress under `ai-visibility-progress-${brandId}` in localStorage, keyed by `'default'` when no brand is selected — shared-browser leak.
- **P2-11** — `analytics-integrations.tsx` stores GA4/GSC IDs in localStorage unencrypted.
- **P2-12** — Array-index `key={idx}` in list renders (articles, ai-visibility) — reconciles wrong on reorder.
- **P2-13** — Share-of-voice math uses float → `toFixed` or integer-cents.
- **P2-14** — Date math uses server-local `new Date()` against UTC timestamps in DB.
- **P2-15** — Missing indexes on frequently-filtered columns (`aiPlatform`, `status`, `createdAt`) across geoRankings, articles, distributions, promptTestRuns, agentTasks.
- **P2-16** — Audit all `getMonth()` comparisons for the same year-ignorance bug as P0-6.
- **P2-17** — `setupStripeProducts()` at boot has no locking. Two simultaneous boots race to create the same product.
- **P2-18** — Vite config has no prod-specific optimizations; sourcemap setting is inherited.
- **P2-19** — Generic `{ error: 'Failed to X' }` responses mask specific failures; add structured error codes.
- **P2-20** — `Promise.all(faqs.map(createFaqItem))` has no partial-failure rollback ([routes.ts:4015](../server/routes.ts#L4015)).
