## The one finding to weigh most carefully
V6-02: after `advanceCitationRun()` marks a run terminal but before
`setAutopilot(... 'completed')` writes, a process restart leaves the brand in
`running_citations` with no active run, so the next resume calls
`runBrandPrompts()` and starts a fresh PAID citation run. The window includes a
`populateBrandDashboard(..., deadlineMs: 120_000)` call, so it is up to two
minutes wide, not a microsecond race.

The orchestrator established that the in-flight path has no attempt cap by
deliberate design and is bounded only by the 6-hour stall demotion, which runs
before the scan in the same sweep.

Answer precisely:
- How many repeat paid runs can occur in the worst case, given how often
  `resumeInFlightAutopilots` actually fires? Find every caller and every
  schedule. Show the arithmetic.
- What is the cheapest correct fix? Consider: writing `autopilot_step = 3` or a
  terminal marker immediately when the slice returns `done` and before
  `populateBrandDashboard`; making the completion write part of the same
  transaction; or having the `else` branch check for a recently-terminal run for
  this autopilot cycle before starting a new one. Recommend ONE, with the
  reasoning, and say what it would break.
- Is this a release blocker, or a follow-up? Defend the answer.

## Deliverable
Write to `.audit/B11-verify/V8-synthesis.md`.

Mandatory sections:

`## Decision` — one of: SHIP / SHIP AFTER LISTED FIXES / DO NOT SHIP. One
paragraph of justification. No hedging.

`## Consolidated findings` — a single deduplicated table, ordered by real
severity after reconciliation, with columns:

`## Production deployment sequence` — a numbered runbook. For each step: the
exact command, the precondition that must hold before running it, the
observable that proves it worked, and the rollback if it does not. Cover in the
right order: merging main into the branch, regenerating the Supabase mirror,
CI, applying 0122/0123/0124, deploying application code, and the post-deploy
checks. State explicitly which steps are irreversible.

`## What could still delete or corrupt production data` — the honest list, with
the conditions that would have to hold. If the answer is "nothing, absent an
operator running a manual command", say that plainly and name the commands.

`## Residual risk accepted` — what ships unfixed and why that is acceptable.

`## Evidence gaps` — what nobody verified, and what it would take to close each.

Be decisive. The reader is the repository owner and wants a yes or no with
conditions, not a survey of opinions.
