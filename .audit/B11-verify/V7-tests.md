## Findings

1. **F-01 | high | `server/routes/contentTypes.ts:85`**

   What is not actually tested: 130 of 179 registrations in changed route modules have no HTTP-level test. The extraction can change route registration, status, response shape, middleware order, or error mapping without a route test failing.

   What could ship broken as a result: A service can pass direct unit tests while the HTTP endpoint calls the wrong service, returns the wrong status, or returns the wrong JSON shape.

   Confidence: high.

2. **F-02 | high | `tests/helpers/destructiveDatabaseTest.ts:59`**

   What is not actually tested: 22 database-gated files skip when `TEST_DATABASE_URL` is absent. Six also require `LOCAL_SUPABASE_TEST=1`. The normal Vitest command can remain green without database coverage.

   What could ship broken as a result: RLS, migrations, tenant isolation, real SQL behavior, and v2 persistence can fail in a database while the reported suite remains green.

   Confidence: high.

3. **F-03 | medium | `server/storage.ts:1065`**

   What is not actually tested: The exported storage object has no test that verifies every domain module contributes its methods.

   What could ship broken as a result: A removed spread can make a storage method undefined at runtime. Compile-time interface checks may catch only missing methods that no other spread supplies.

   Confidence: high.

4. **F-04 | medium | `shared/schema/platform.ts:171`**

   What is not actually tested: No test checks the four new Drizzle foreign-key references or their delete actions.

   What could ship broken as a result: The schema reader and future schema generation can lose a relationship or delete action while the already migrated database continues to hide the drift.

   Confidence: high.

5. **F-05 | medium | `shared/schema/identity.ts:16`**

   What is not actually tested: No test checks `.notNull()` metadata across the shared schema. The migration checks inspect column names, not nullability.

   What could ship broken as a result: A column can become nullable in generated schema output without a failing test. Inserts and data contracts can then accept invalid incomplete rows.

   Confidence: high.

6. **F-06 | medium | `tests/unit/dashboardPreDataState.test.ts:20`**

   What is not actually tested: The old five negative `hasMeasured` cases were local helper tests. The replacement imports the real hook but checks only one positive completed-scan case.

   What could ship broken as a result: An empty or pre-scan dashboard can report measured data without this test failing.

   Confidence: high.

7. **F-07 | low | `tests/unit/citationCronUnconditional.test.ts:16`**

   What is not actually tested: The citation selector still uses source-text assertions. It does not execute the query against a database or inspect the produced SQL.

   What could ship broken as a result: A query refactor can change deleted-brand or paid-tier selection while the route tests remain green. A source rename can also create a false failure without a behavior change.

   Confidence: high.

8. **F-08 | medium | `vitest.config.ts:22`**

   What is not actually tested: `npm test` excludes all Playwright files. The suite result does not include browser journeys, local fake-generation flows, or tour flows.

   What could ship broken as a result: A client or browser integration regression can ship with the reported Vitest count unchanged.

   Confidence: high.

## Verdict

The green suite earns moderate confidence for covered unit and route paths, but not database, browser, schema metadata, storage composition, or the 130 untested changed route registrations; 352 test code files were examined by whole-tree scan and 46 were sampled in source-level review.
