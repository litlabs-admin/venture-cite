## Cross-domain calls stay as 
Some methods call others that live in different domains. Do NOT import the other
domain module to resolve that. Object spread preserves  binding to the
composed  object, so  resolves at runtime without
an import, and  gives TypeScript the same view. Importing
across domains would build a dependency tangle the composition exists to avoid.

Where a method used  inside the class, it keeps using . You
may need  as a first parameter for TypeScript to accept it.

## Wiring

 composes the result:

    export const storage: IStorage = { ...promptsStorage, ...(whatever else exists) };

While  still holds the remaining methods, spread the class
instance too, so the composition stays complete. TypeScript enforces this: an
incomplete spread produces TS2741 naming the missing method.
