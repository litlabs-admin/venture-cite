# INV02-ownership route ownership checks

## The rule as implemented
File: server/routes.ts:80,88,124,129
Rule: The application attaches a verified user, requires a Bearer token for non-public `/api/` routes, checks body and query `brandId` values, and checks every `:brandId` path value.

File: server/auth.ts:44,116,141,157,252
Rule: `isAuthenticated` loads the user from the Bearer token. `checkBrandOwnership` selects the brand with `brands.userId = user.id`. A miss returns 404. `brandIdParamHandler` uses that check for route parameters.

File: server/lib/ownership.ts:16,34,44,155,207
Rule: `requireUser` obtains the authenticated user. The `require*` functions load an item through its brand or user owner. They return 404 on an ownership miss.

The `:brandId` handler was registered after many routes. I proved its behavior with Express 5. A route registered first still ran the parameter handler when matched.

## Violations
### V-01 | high
Item: GET `/api/admin/scrape/:runId`
Defined at: server/routes/adminScrapeInspector.ts:20
Why it violates the invariant: The handler returns a scrape run, its brand, pages, logs, events, and facts. It checks only `isAdmin`.
How it fails (concrete sequence): An administrator sends a Bearer token and another tenant's run ID. The handler loads that run without comparing `run.brandId` to the administrator's owned brands. It returns the tenant data.
Confidence: high

### V-02 | high
Item: POST `/api/admin/scrape/fact/:factId/reverify`
Defined at: server/routes/adminScrapeInspector.ts:113
Why it violates the invariant: The handler passes an arbitrary fact ID to `reverifyFact` after only `isAdmin`.
How it fails (concrete sequence): An administrator sends a Bearer token and another tenant's fact ID. `reverifyFact` reads and updates that fact. No code confirms that the fact brand belongs to the caller.
Confidence: high

### V-03 | high
Item: GET `/api/admin/scrape/runs/recent`
Defined at: server/routes/adminScrapeInspector.ts:165
Why it violates the invariant: The handler returns recent scrape runs for every brand. It has no user or brand filter.
How it fails (concrete sequence): An administrator sends a Bearer token. The handler selects the 50 newest runs, including other tenants' brand IDs and scrape state.
Confidence: high
