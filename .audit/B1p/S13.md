### F-S13-003 | high | concurrency
File: server/databaseStorage.ts:3916-3943

What the code does:

`acceptFact` updates the selected row. It then runs a separate update for conflicting rows when dismissal is enabled.

Why it is wrong:

The two writes have no transaction or conditional selection that protects the choice from another writer.

How it fails (concrete input or sequence):

Two requests accept opposite facts for the same key. Each request can accept one row and dismiss the other row. Both rows can then have `acceptedAt` and `dismissedAt`, so no single choice remains.
