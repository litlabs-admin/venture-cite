You are checking ONE invariant across the whole test suite. This is not a file
review. Report only violations of the stated invariant.

## The invariant

Every test asserts the behaviour of the application. A test that passes must mean
the application works; a test that fails must mean the application is broken.

## What violates it

1. Tautological test. The test defines its own copy of the logic and asserts
   against that copy, so it would pass if the real implementation were deleted.
   A known example is tests/component/PreviewParam.test.tsx, which redefines
   isAdmin() locally. Use it to calibrate, then find the others.
2. The test mocks the thing it claims to test, so only the mock is exercised.
3. The test asserts nothing meaningful. A bare toBeDefined() or toBeTruthy() as
   the only assertion, or an assertion that cannot fail.
4. The test is skipped or gated in a way that means it never runs, without that
   being obvious to someone reading a green run.
5. The test asserts implementation detail rather than behaviour, so a correct
   refactor breaks it. Report these as low severity.

## Method

1. Enumerate every test file under tests/.
2. For each, determine what it imports from the application. A test that imports
   nothing from server/, client/, shared/ or src/ is a strong candidate for
   violation 1.
3. Check what each test mocks against what it claims to verify.
4. Count real assertions per test.
5. Check the gating: which tests run under `npm test` with no database, and which
   silently skip. tests/helpers/destructiveDatabaseTest.ts is the gate.
