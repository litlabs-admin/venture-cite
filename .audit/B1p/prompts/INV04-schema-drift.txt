## The invariant

Every column declared in shared/schema.ts exists in the migrations, and every column created by the migrations is declared in shared/schema.ts.

Rationale: A column in the code but not the database throws at runtime. A column in the database but not the code is either dead or silently unused. Both have already happened in this repository.

## Method

1. Parse every pgTable definition in shared/schema.ts. Build the full table and column inventory.
2. Parse every file in migrations/. Track create table, add column, drop column, and rename in order, to compute the final schema.
3. Compare the two inventories in both directions.
4. Report every column in one and not the other, and every type mismatch you can determine.
