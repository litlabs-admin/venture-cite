## The invariant

Every write path that reads a value and then writes a value derived from it is safe when two users, two requests, or two workers run it at the same time.

Rationale: This product must serve many users at once. A lost update or a double charge is a real user-visible failure.

## Method

1. Find every read-modify-write sequence in server/. Look for a select followed by an update or insert that depends on the selected value, counters, quota and limit checks, status transitions, slot claims, and queue or outbox draining.
2. For each, determine the protection: a transaction with an appropriate isolation level, a row lock such as select for update, a unique constraint, an advisory lock, an atomic SQL expression, or a compare and set.
3. Report every sequence with no protection, and state the interleaving that breaks it.
4. Note separately any operation that is not idempotent under retry, since this system retries jobs.
