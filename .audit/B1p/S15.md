### F-S15-001 | high | concurrency
File: server/lib/factAgent/v2/factScrapeBackstop.ts:58-72
What the code does: The backstop holds a PostgreSQL transaction advisory lock before it calls `runAggregate`.
Why it is wrong: The full pipeline uses a row lease from `job_leases`, not this PostgreSQL advisory lock (`runFullScrape.ts:159-163`). The two paths do not exclude each other.
How it fails: Let a full scrape stay stale for more than 60 seconds after it creates its run. The backstop aggregates and terminates that run while the full scrape still writes pages and facts. A new scrape can then start because the run is terminal.
Confidence: high

### F-S15-010 | medium | concurrency
File: server/lib/factAgent/v2/persistPasteFacts.ts:25-53
What the code does: Paste persistence deletes all paste rows and inserts the new rows in one transaction. User persistence uses the same delete-then-insert shape at `persistUserFacts.ts:27-78`.
Why it is wrong: Neither transaction takes a per-brand lock or uses a replacement guard. A transaction boundary does not serialize two requests for the same brand.
