## F-S03-client-hooks-005 | CONFIRMED

Original claim: A stream for one thread can append output to another selected thread.

What I checked: `client/src/hooks/useChatbot.ts:91-116`, `client/src/hooks/useChatbot.ts:161-270`, `client/src/hooks/useChatbot.ts:294-298`, `client/src/components/EducationAssistant.tsx:270-280`, `client/src/components/chatbot/HistoryView.tsx:105-155`, and `server/routes/assistant.ts:368-381`.

Verdict reasoning: `selectThread` changes the active ID without stopping the controller. The delta handler appends to shared `messages` without checking the stream thread ID. A completed thread B ends with an assistant message. Later deltas from A append to that message in B. The server stores the response under A, so the error changes the displayed transcript only.

Reachable path (CONFIRMED only): `client/src/components/EducationAssistant.tsx:271-280` -> `client/src/components/chatbot/HistoryView.tsx:105-155` -> `client/src/hooks/useChatbot.ts:294-298` -> `client/src/hooks/useChatbot.ts:239-250` -> transcript for B changes.

Corrected severity (CONFIRMED only): medium. The error can mislead the user, but it does not store A output in B.

## F-S03-client-hooks-004 | CONFIRMED

Original claim: Regenerate sends the old local transcript before React applies the deletion.

What I checked: `client/src/hooks/useChatbot.ts:161-203`, `client/src/hooks/useChatbot.ts:279-288`, `client/src/components/EducationAssistant.tsx:307-319`, `client/src/components/chatbot/MessageBubble.tsx:69-92`, and `server/routes/assistant.ts:194-230`, `server/routes/assistant.ts:276-289`.

Verdict reasoning: `regenerate` calls `setMessages` and then calls the `send` closure from the same render. For `[user U, assistant A]`, `send` builds `[U, A, U]`. The server persists the final U, then loads the existing U and A with it. The model receives the repeated user turn and prior assistant reply.

Reachable path (CONFIRMED only): `client/src/components/chatbot/MessageBubble.tsx:86-92` -> `client/src/components/EducationAssistant.tsx:307-319` -> `client/src/hooks/useChatbot.ts:279-285` -> `client/src/hooks/useChatbot.ts:182-203` -> `server/routes/assistant.ts:194-230` -> `server/routes/assistant.ts:276-289`.

Corrected severity (CONFIRMED only): high.

## F-S05-002 | CONFIRMED

Original claim: Opening the tutor can select a thread for a different current brand.

What I checked: `client/src/hooks/useChatbot.ts:42-83`, `client/src/hooks/useChatbot.ts:161-203`, `server/routes/assistant.ts:61-80`, `server/routes/assistant.ts:242-274`, `server/databaseStorage.ts:4422-4448`, and `tests/unit/EducationAssistant.test.tsx:170-185`.

Verdict reasoning: The list query filters only by user ID. The first-load effect selects its first result without checking `brandId`. Corrected severity (CONFIRMED only): medium. The affected brands belong to the same user, but the response and future history use the wrong brand context.

## F-S05-004 | REFUTED

Original claim: Sending refreshes only the thread list and leaves the active message query fresh for 30 seconds.

What I checked: `client/src/hooks/useChatbot.ts:24-25`, `client/src/hooks/useChatbot.ts:91-116`, `client/src/hooks/useChatbot.ts:268-270`, `node_modules/@tanstack/query-core/src/utils.ts:143-166`, and `node_modules/@tanstack/query-core/src/queryClient.ts:291-310`.

Verdict reasoning: `THREADS_KEY` is the prefix of every message key. TanStack Query applies a non-exact query filter as a partial key match. The invalidation at line 269 therefore invalidates the active message query. TanStack Query then refetches active matched queries. The 30-second stale time does not preserve the old transcript after a completed send.
