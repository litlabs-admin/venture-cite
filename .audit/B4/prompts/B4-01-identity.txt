Extract the identity domain from `shared/schema.ts` into `shared/schema/identity.ts`.

This is the first of seven modules. It has to establish the pattern the other six
follow, so the barrel mechanism matters more than the speed.

## What moves

Lines 23 to 241 of `shared/schema.ts`, which form a contiguous, self-contained
block. Confirm the boundaries yourself before you cut; do not trust these numbers
blindly.

Tables: `users`, `betaInviteCodes`, `waitlist`.

Everything declared alongside them moves too: `usageLimits`, `SELLABLE_TIERS`,
`SellableTier`, `PLAN_PRICE_CENTS`, `PAYING_TIERS`, `TRIAL_DAYS`, `UpsertUser`,
`User`, `InsertUser`, `BetaInviteCode`, `InsertBetaInviteCode`,
`insertWaitlistSchema`, `Waitlist`, `InsertWaitlist`, and any others in that
range. Comments move with the code they describe.

None of these three tables reference another table, which is why this module goes
first.

## What must not change

Nothing else. This is a move, not a refactor.

- No column, type, name, or default changes.
- No new migration. The database shape is untouched.
- **No consumer edits.** 147 files import this schema. If a single import
  elsewhere has to change, your barrel is wrong. Fix the barrel, not the caller.

`shared/schema.ts` becomes a barrel that re-exports the new module alongside
everything still in it, so `import { users } from "@shared/schema"` and
`import * as schema from "@shared/schema"` both keep working exactly as now.
25 files use the wildcard form, so a named-only re-export is not sufficient.

## Method

1. Capture the export surface first if you want your own reference:
   `npx tsx scripts/schemaExportSurface.ts`
2. Confirm the real boundaries of the block. Read the code above line 23 and
   below line 241.
3. Create `shared/schema/identity.ts` and move the block verbatim.
4. Make `shared/schema.ts` re-export it.
5. Run the gates below. Fix what fails.

## Acceptance, in this order

1. `npx tsx scripts/schemaExportSurface.ts --check .audit/B4/schema-exports-before.txt`
   must print "Export surface unchanged. 260 exports." This is the gate that
   matters. A dropped export is invisible to the compiler when nothing happens to
   reference it today, and it breaks at runtime later.
2. `npm run check`
3. `npm run lint` and `npm run format:check`
4. `npm test` with `--maxWorkers=1`

Show the output of each.

## Report

Write `.audit/B4/B4-01-identity-report.md` with: the real line boundaries you

State plainly whether any consumer file changed. If one did, say which and why,
rather than presenting it as success.
